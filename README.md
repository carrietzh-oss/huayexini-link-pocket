# 花野链接夹

一个轻量、开源的浏览器链接收藏夹。看到以后还想回来的内容时，在 X、Instagram 或 YouTube 的单条博文/视频点击粉色 `＋`，插件会保存这一条内容。

## 它做什么

- 在 X、Instagram、YouTube 信息流里识别单条博文或视频的永久链接。
- 自动保存标题、作者、正文摘要、视频/图片封面和来源平台。
- 预设分类和后来新建的分类都参与自动匹配；新分类可设置匹配词，弹窗里仍可手动调整。
- 点击后提示“已保存到哪个分类”。
- 收藏卡片展示封面、标题、作者和内容说明，方便以后快速判断它是什么。
- 支持新建、改名、排序和删除分类。
- 在收藏夹里拖动卡片，即可移动到其他目录。
- 相同网址再次保存时更新原记录，不生成重复链接。
- 点击“打开原页面”直接回到收藏来源。
- 也可以在收藏夹页面手动粘贴一个链接。

如果你在信息流里看不到粉色 `＋`：

1. 在 `chrome://extensions/` 打开“开发者模式”。
2. 点击花野链接夹的“重新加载”。
3. 刷新已经打开的 X、Instagram 或 YouTube 页面。

默认分类包括：

- 待整理
- 需要体验的 AI 产品
- 需要阅读的内容
- 可参考的设计以及视频
- 可以落地的想法
- 好用 Prompt
- Web Coding Idea

## 安装（Chrome / Edge）

1. 点击 GitHub 页面右上方的 `Code → Download ZIP`。
2. 解压下载的 ZIP。
3. Chrome 地址栏打开 `chrome://extensions/`。
4. 打开右上角“开发者模式”。
5. 点击“加载已解压的扩展程序”。
6. 选择解压后的仓库文件夹（里面能直接看到 `manifest.json`）。
7. 把“花野链接夹”固定到浏览器工具栏。

无需终端，无需 API Key。

### 升级和找回旧收藏

Chrome 的收藏数据属于某个扩展 ID。每次下载 ZIP 解压到新的文件夹，再用“加载已解压的扩展程序”安装，可能变成另一个扩展，看到空收藏夹。请不要删除旧扩展。

1. 在 `chrome://extensions/` 找到**原来有收藏的花野链接夹**，记下扩展 ID，并找到当初在 Finder 里选择的原安装文件夹。
2. 将本仓库新版文件覆盖到**原扩展正在加载的那个文件夹**，不要新建另一份安装；回到 Chrome 点击该扩展的“重新加载”，原收藏应当出现。
3. 先在收藏夹点击“导出收藏备份”，保存 JSON 文件。以后换电脑或确实需要新建安装，在新扩展点击“导入旧版备份”，选择该文件；导入会合并链接，不清空已有内容。
4. 确认新旧收藏数量和分类无误后，再决定是否移除多余的扩展。

如果原扩展已经卸载且没有备份，Chrome 可能已经清掉原扩展的本地数据；当前版本无法凭仓库代码恢复这些个人收藏。

## 使用

1. 打开 X、Instagram 或 YouTube 信息流。
2. 鼠标移动到目标博文或视频上。
3. 点击内容卡片上的粉色 `＋`。
4. 插件会识别单条链接、标题、作者和封面，并自动分类。
5. 点击弹窗底部“打开全部链接”，进入分类收藏夹。

## 自定义分类自动匹配

在收藏夹点击“＋ 新建分类”，填写名称（如“剪辑”），可选填匹配词（如“转场、剪映、Premiere”）。名称本身也参与匹配。已创建的“剪辑”分类无需重建：点击“管理分类”旁的“词”即可补充匹配词。页面上的粉色“＋”和弹窗保存共用这套规则。

匹配只使用本地的标题、摘要、备注等文字和关键词，不调用 AI。内容没出现分类名或匹配词时，不能保证自动识别；可在弹窗选择或在收藏夹拖动更正。已保存的链接不会因为新增分类而自动搬家。

## 数据和隐私

- 只在 X、Instagram、YouTube 页面运行，用于识别你主动点击的单条内容。
- 保存链接、标题、正文摘要、作者、封面地址、分类和你主动填写的备注。
- 不读取密码、表单内容或私信。保存封面时，扩展仅向对应平台的图片域名请求图片。
- 不连接第三方 AI，也不会把收藏上传到服务器。
- 能获取的封面会压缩后保存在浏览器本地；如果平台没有提供图片、限制下载或图片已失效，卡片可能显示占位图。打开原内容详情页再次点 `＋` 可重试；有原封面地址时也可点卡片的“重试封面”。
- 数据保存在浏览器扩展的本地存储中；卸载扩展会同时删除本地记录。
- 当前版本暂不连接 Obsidian。

## 后续计划

先实际使用一段时间。确认哪些链接值得长期保留后，再决定是否增加 Obsidian 沉淀功能。


## v0.3.5

- 修复 Instagram 收藏卡片封面经常变成占位图的问题。
- 保存 Instagram 内容时，会把临时 CDN 图片转换为本地压缩缩略图后再保存。
- 收藏夹打开时，会尝试自动修复仍然有效的旧 Instagram 封面。

## v0.3.6

- 新建分类也参与自动分类；支持设置和编辑自定义匹配词。
- 原有收藏数据及分类保持不变；新规则只影响之后保存的链接。

## v0.3.7

- 增加收藏 JSON 备份导出与合并导入，便于换安装路径和设备时迁移。
- X、Instagram、YouTube 封面保存时尝试压缩为本地缩略图；YouTube 优先用视频 ID 获取封面。
- 保存请求由后台按顺序处理，避免快速连续点击时覆盖上一条；打开收藏夹不再写回旧快照。

## v0.3.8

- 扩展 Instagram、X、YouTube 常见图片域名的本地缓存支持；图片请求失败时用另一种凭据模式重试。
- Instagram 详情页与部分视频背景图增加封面提取路径；YouTube 保留按视频 ID 获取缩略图。
- 保存成功但封面未存入本地时，提示具体原因（页面未提取到图片、图片域名不支持、超时或图片服务器错误）。链接仍会保存。
- 更新前先在收藏夹点“导出收藏备份”；更新时覆盖同一个插件文件夹，在 Chrome 中重新加载，避免生成另一个扩展 ID。

## v0.3.9

- YouTube 优先尝试当前视频实际显示的缩略图，失败时依次尝试视频 ID 对应的 WebP、高清 JPG 和中等画质 JPG；旧 YouTube 收藏也可在卡片中点击“重试封面”。
- Instagram、X 的候选图片地址会依次尝试，首次下载失败时不再直接放弃封面。
- 移动链接、删除链接和删除分类与保存操作共用队列，避免同时操作时旧页面数据覆盖新收藏。

## v0.3.10

- 封面最长边提高到 960 像素，以 WebP 质量 0.86 缓存；旧版 320 像素的本地缩略图需要重新打开原内容并保存才能替换。
- YouTube 优先选取视频 ID 对应的高分辨率封面，并跳过尺寸过小的占位图。
- Instagram 选取帖子的首张媒体图，避免将轮播内页当作封面；X 视频优先使用视频封面，图片优先请求原图尺寸。
- 下载成功的图片会保存原始地址供“重试封面”使用；过小的预览图会被跳过。现有模糊封面需要重新打开原内容保存一次，YouTube 可直接点击“重试封面”。
